# 블로그 태그 기준

2026-11-18 제정. 그때 상태는 **글 75편에 태그 153종, 그중 105종이 1회만** 쓰였다.
태그가 이러면 필터가 아니라 그냥 목록이다. 아래는 **고정 어휘**다 — 여기 없는 태그는 새로 만들지 않는다.

## 규칙 네 줄

1. **글당 3~5개.** 지금은 5~7개가 많은데 줄인다.
2. **세 축에서 고른다** — 독자(1개 필수) · 주제(1~2개) · 기술(0~3개).
3. **새 태그는 "앞으로 3편 이상에 붙을 것"이 확실할 때만** 만든다. 아니면 기존 것을 쓴다.
4. **한 번 쓰고 말 고유명사는 태그로 만들지 않는다.** 본문에 쓰면 된다 (예: VoiceOver, Workers KV, HMAC, Lighthouse).

## 축 1 — 독자 (정확히 1개, 필수)

| 태그     | 쓸 때                                        |
| -------- | -------------------------------------------- |
| `개발자` | 코드·설계·도구 이야기                        |
| `사무직` | 개발자가 아닌 실무자가 AI·도구를 쓰는 이야기 |

둘 중 하나는 반드시 붙인다. 이 축이 블로그의 가장 큰 갈림길이고, 독자가 제일 먼저 거르는 기준이다.

> `프론트엔드`는 폐기한다 — 개발 글 거의 전부에 붙어서 걸러지는 게 없었다. 그 자리를 `개발자`가 대신한다.

## 축 2 — 주제 (1~2개)

| 태그           | 쓸 때                          |
| -------------- | ------------------------------ |
| `접근성`       | KWCAG·WCAG·화면낭독기·키보드   |
| `성능`         | 측정·번들·렌더링               |
| `디자인시스템` | 컴포넌트 구조·토큰·배포        |
| `아키텍처`     | 레이어·경계·계약               |
| `자동화`       | CI·스크립트로 사람 일을 줄이기 |
| `공공`         | 공공기관 납품·입찰·검수        |
| `납품·운영`    | 설치·배포·장애·기록            |
| `협업`         | 애자일·리뷰·일정·역할          |
| `AI로 만들기`  | AI와 함께 만드는 과정          |
| `경리`         | 경리 실무 (사무직 글 전용)     |

## 축 3 — 기술 (0~3개)

`React` · `Vue` · `Next.js` · `Tailwind CSS` · `TypeScript` · `KRDS` · `KWCAG` · `Claude Code` · `Figma` · `CSS` · `CI`

제품·도구 이름 그대로 쓰되 **공식 표기**를 따른다 (`Tailwind CSS`, `Next.js`).

## 통합 표 (옛 태그 → 새 태그)

| 옛 태그                                                        | 바꿀 것                                                     |
| -------------------------------------------------------------- | ----------------------------------------------------------- |
| `프론트엔드`                                                   | `개발자`                                                    |
| `웹접근성`                                                     | `접근성`                                                    |
| `ARIA` · `키보드` · `스크린리더` · `WCAG` · `VPAT` · `axe`     | `접근성` (본문에서 다룬다)                                  |
| `성능최적화` · `측정` · `리렌더` · `번들사이즈`                | `성능`                                                      |
| `업무 자동화`                                                  | `자동화`                                                    |
| `공공기관` · `공공SI` · `전자정부프레임워크`                   | `공공`                                                      |
| `컴포넌트` · `디자인토큰` · `CSS변수` · `shadcn` · `Storybook` | `디자인시스템`                                              |
| `애자일` · `스프린트` · `코드리뷰` · `팀협업` · `PR`           | `협업`                                                      |
| `AI` · `AI 입문` · `AI 도구` · `Claude` · `프롬프트`           | `AI로 만들기` 또는 `Claude Code`                            |
| `개발도구` · `DX` · `CI/CD` · `GitHub Actions`                 | `자동화` 또는 `CI`                                          |
| `HANUI`                                                        | 뺀다 — 이 블로그 글 상당수가 HANUI 이야기라 걸러지지 않는다 |

## 쓰는 예

```yaml
# 개발 글
tags: ['개발자', '접근성', 'KRDS', 'Vue']

# 사무직 글
tags: ['사무직', '경리', '자동화']
```

## 지키는 법

새 글을 쓸 때 **이 파일의 어휘 밖 태그를 쓰지 않는다.** 꼭 필요하면 먼저 이 파일에 추가하고,
추가할 때 "앞으로 3편 이상에 붙을까"를 자문한다. 아니면 추가하지 않는다.

기존 75편 일괄 적용은 **아직 안 했다**(2026-11-18 기준). 새 글부터 적용하고,
옛 글은 손댈 일이 있을 때 함께 고친다.
