# 블로그 예약 발행 큐

여기에 둔 글은 **사이트에 안 보여요.** 발행일이 되면 자동으로 올라갑니다.

## 어떻게 동작하나

- 매일 GitHub Actions(`.github/workflows/daily-publish.yml`)가 이 폴더를 훑어,
  프론트매터 `date`가 **오늘 이하**인 글을 `apps/docs/src/content/blog/`로 옮기고 커밋·푸시합니다.
- 푸시되면 Vercel이 자동 배포 → hanui.io에 글이 등장합니다.
- 하루 걸러도 밀린 글을 다음 실행 때 모두 따라잡습니다.
- 남은 예약글이 3편 미만이면 "재고 부족" GitHub 이슈로 알려줍니다.

### 예약은 하루 두 번, 12시간 떼어 둔다

- `00:19 KST`(본 실행) / `12:19 KST`(대체 실행)
- **시각은 희망이지 약속이 아닙니다.** GitHub 스케줄러는 cron 시각보다 늦게 실행을 만들고
  (실측 지연 +3h59m ~ +6h07m), 아예 건너뛰기도 합니다.
- 2026-11-16에 예약 두 번이 **모두** 건너뛰어져 11-17 글이 발행되지 않았습니다. 그때 두 예약은
  2h22m 간격이었습니다. 스케줄러가 한 시간대를 버리면 그 안의 예약은 같이 죽습니다 —
  좁은 창에 몰아 넣은 이중화는 이중화가 아닙니다. **수를 늘리는 게 아니라 거리를 벌리는 문제**입니다.

## 발행이 빠지면 어떻게 알게 되나

알림이 두 겹이고, **서로 다른 곳에서 죽습니다.** 한쪽이 멈춰도 다른 쪽이 남습니다.

| 무엇을 잡나              | 어디서 보나                     | 어떻게 알리나                                 |
| ------------------------ | ------------------------------- | --------------------------------------------- |
| 실행은 됐는데 **늦었다** | GitHub Actions (발행 실행 자신) | `blog-publish-missed` 이슈에 "며칠 늦음" 기록 |
| 실행이 **아예 없었다**   | **Vercel Cron** (13:00 KST)     | 같은 이슈를 열고, 큐가 정리되면 자동으로 닫음 |

부재 감시는 `apps/docs/src/app/api/cron/blog-watch/route.ts`입니다. 설계상 중요한 점 두 개:

- **일부러 GitHub Actions가 아닙니다.** 부재를 감시하는 코드를 같은 스케줄러에 올리면
  스케줄러가 죽는 날 감시도 같이 조용히 죽습니다.
- **실행 이력이 아니라 큐 상태를 봅니다.** `date`가 어제 이하인 글이 큐에 남아 있으면
  그 글을 가져가야 했던 실행이 없었던 것입니다. 그래서 감시가 하루 빠져도 다음 날 똑같이
  잡아내고(멱등), 하루 중 아무 때나 돌려도 오판하지 않습니다. **오늘 치 글은 세지 않습니다** —
  발행이 지연 중일 수 있고, 지연은 부재가 아닙니다.

날짜 판정은 발행과 감시가 `apps/docs/src/lib/blog-queue.mjs` 한 모듈을 같이 씁니다.
따로 세면 "발행은 했다는데 감시는 밀렸다고 한다"가 됩니다. 경계 테스트:

```bash
node --test apps/docs/src/lib/blog-queue.test.mjs
```

### Vercel 설정 (한 번만)

프로젝트 환경 변수에 두 개가 있어야 합니다. **없으면 라우트가 503으로 실패합니다** —
조용히 넘어가지 않습니다(조용히 넘어가는 감시가 바로 이 코드가 고치려는 결함입니다).

| 변수                      | 쓰임                                                                 |
| ------------------------- | -------------------------------------------------------------------- |
| `CRON_SECRET`             | Vercel이 `Authorization: Bearer`로 보내는 값. 아무 긴 난수           |
| `BLOG_WATCH_GITHUB_TOKEN` | 이슈를 열 권한(fine-grained PAT, 이 저장소 `Issues: Read and write`) |

배포 후 Vercel → Settings → **Cron Jobs**에 등록됐는지 확인합니다.
(프로젝트 Root Directory가 `apps/docs`로 잡혀 있으면 `crons` 블록을
저장소 루트 `vercel.json`이 아니라 `apps/docs/vercel.json`에 둬야 합니다.)

### 이 감시도 못 보는 것

이 라우트 자체가 죽으면 아무도 모릅니다. **감시자의 감시자는 없습니다.**
완전히 막으려면 "침묵이 곧 알람"인 외부 dead man's switch가 필요합니다.
지금 보장하는 건 발행과 감시가 **서로 다른 곳에서 죽는다**는 것까지입니다.

## 쟁여두는 법 (시간 날 때 몰아서)

1. 글을 `apps/docs/blog-queue/[slug].mdx`로 작성한다. (형식은 `/blog` 커맨드와 동일)
2. 프론트매터 `date`에 **원하는 발행일**을 미래 날짜로 적는다.
   - 하루 한 편씩 내보내려면 날짜를 하루 간격으로 매긴다. 예: 06-27, 06-28, 06-29…
   - 같은 날짜를 여러 글에 주면 그날 한꺼번에 나가니(=배치 발행) 피한다.
3. 커밋·푸시한다. 끝.

## 수동 발행

지금 당장 발행 대상을 확인하거나 즉시 내보내고 싶으면:

```bash
# 로컬에서 미리보기(파일 안 옮김)
DRY_RUN=1 node scripts/publish-due-posts.mjs

# GitHub Actions 탭 → "Daily Blog Publish" → Run workflow (수동 트리거)
```
