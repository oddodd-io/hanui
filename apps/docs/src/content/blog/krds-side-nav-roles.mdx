[3편](/blog/krds-mobile-menu-nine)에서 모바일 전체메뉴의 결함 9건을 봤어요. 그중 5번이 **"`tablist` 역할을 선언했는데 방향키 동작이 없다"**였고, 저는 **역할을 지키고 동작을 채우는 쪽**으로 갔습니다.

오늘은 **완전히 같은 문제에서 반대 결정**을 한 이야기예요. 사이드 메뉴(LNB)입니다.

> **확인 기준: KRDS v1.1.0, 2026-09-30 확인.** 이건 화면 폭과 무관해요. 3편과 달리 모든 폭에서 재현됩니다.

## 원본은 메뉴바라고 말합니다

KRDS `side_navigation.html`의 구조예요.

```html
<ul class="lnb-list" role="menubar">
  <li class="lnb-item active" role="none">
    <button class="lnb-btn lnb-toggle" role="menuitem" aria-expanded="true">2Depth-menu</button>
    <ul id="lnbmenu-1" role="menu">
      <li class="lnb-subitem" role="none">
        <a href="#" class="lnb-btn lnb-link" role="menuitem">3Depth-link</a>
```

`menubar` / `menu` / `menuitem` / `none`까지 **ARIA 메뉴 패턴을 정석대로 선언**합니다. 꼼꼼해 보여요.

그런데 동작하는 JS를 열어보면요.

```
krds_sideNavigation (ui-script.js L565–696)
  → keydown 핸들러: 0건
  → ArrowUp/ArrowDown/Home/End: 0건
  → role 문자열: 0건
```

**132줄 전체에 키보드 처리가 한 줄도 없습니다.** 클릭 이벤트만 붙여요.

```js
toggleButton.addEventListener('click', () => {
  const expand = toggleButton.getAttribute('aria-expanded') !== 'true';
  this.setActiveNav(toggleButton, expand);
});
```

## 역할은 약속이에요

이게 왜 문제인지는 3편에서 쓴 그대로입니다. 역할을 선언하는 건 **사용자에게 조작법을 약속하는 것**이에요.

`menubar`를 만나면 화면낭독기는 "메뉴 막대"라고 읽고, 사용자는 **방향키를 누릅니다.** 그게 메뉴의 규칙이니까요. 아무 일도 안 일어나면 "이 사이트 고장났나" 하고 끝나요.

게다가 메뉴 패턴은 탭보다 요구가 많습니다. 방향키로 항목 이동, 좌우키로 하위 메뉴 열고 닫기, 타자 치면 그 글자로 시작하는 항목으로 점프, 그리고 **메뉴 전체가 Tab 정지점 하나**여야 해요.

## 그래서 반대 결정을 했어요

전체메뉴에서는 동작을 채웠는데, 여기서는 **역할을 전부 뺐습니다.**

갈린 지점은 하나예요. **그게 실제로 그렇게 생겼느냐.**

전체메뉴의 1depth 목록은 **진짜 탭처럼 생겼습니다.** 가로로 나란히 있고, 하나를 고르면 아래 내용이 바뀌어요. 사용자가 "탭"이라고 들었을 때 보이는 것과 어긋나지 않습니다. 그러면 약속을 지키는 게 맞아요.

사이드 메뉴는 아니에요. **세로로 쌓인 링크 목록**이고, 누르면 그냥 그 페이지로 갑니다. 애플리케이션 메뉴(파일·편집·보기 같은)가 아니라 **사이트 내비게이션**이에요.

ARIA APG도 그렇게 말합니다. 사이트 내비게이션은 메뉴 패턴이 아니라 **disclosure navigation** — 그냥 목록과 `aria-expanded` 버튼이에요.

```
- menubar/menu/menuitem 역할을 쓰지 않는다. 방향키 동작 없이 menu 역할을 쓰면 스크린리더 사용자가 기대한 조작이
  동작하지 않으므로, 사이트 내비게이션 권고(APG disclosure navigation)대로 목록 + aria-expanded 버튼으로 둔다.
```

컴포넌트 머리에 적어둔 이유입니다. **역할을 떼면 "링크 목록"으로 읽히고, 사용자는 Tab으로 넘어가요.** 그게 실제 동작과 맞습니다.

## 떼도 아무것도 안 깨졌어요

걱정한 게 있었어요. KRDS CSS가 `[role=menubar]` 같은 선택자로 모양을 잡고 있으면, 역할을 빼는 순간 디자인이 무너집니다.

확인해봤어요.

```
vendor/.../scss/component/_side_navigation.scss 에서 [role 일치: 0건
```

**전부 클래스 선택자였습니다.** `.lnb-list`, `.lnb-item`, `.lnb-btn`… 그래서 역할만 떼고 마크업·클래스는 그대로 뒀는데 화면이 똑같아요.

보완 파일(`_hanui-fixes.scss`)에도 사이드 메뉴 규칙이 **한 줄도 안 들어갔습니다.** CSS를 전혀 안 건드리고 끝난 유일한 컴포넌트예요.

## 덤으로 찾은 것 — 불리지 않는 함수

역할을 보다가 옆에 있는 걸 발견했어요.

```js
setActiveCurrentPage() {
  ...
  link.setAttribute('aria-current', 'page');
}
```

현재 페이지에 `aria-current="page"`를 붙여주는 함수가 **제대로 들어 있습니다.** 그런데요.

```js
init() {
  this.setupSideNavLists();
  this.setupToggleEvents();
  this.setupPopupEvents();
}
```

**`init()`이 안 부릅니다.** 파일 전체에서 `setActiveCurrentPage`를 찾으면 **정의된 685번째 줄 하나만 나와요.** 호출부가 없습니다.

그러니까 원본을 그대로 쓰면 **현재 페이지 표시가 아예 안 붙어요.** 화면낭독기 사용자는 사이드 메뉴 열 곳 중 지금 어디에 있는지 알 수 없습니다. 눈으로 보는 사람에게는 색이 다르니 명백한데요.

바로 옆 `setupToggleEvents`에는 이런 줄도 있었어요.

```js
//this.toggleMenu(toggleButton, expand); 클릭 시 해당 버튼만 활성화 상태로 변경되어 해당 이벤트 주석처리.
//this.closeSiblingMenus(toggleButton);  클릭 시 해당 버튼만 활성화 상태로 변경되어 해당 이벤트 주석처리.
```

[3편 1번](/blog/krds-mobile-menu-nine)의 `aria-expanded` 주석 처리와 **같은 모양**이에요. 잠깐 끄고 되돌리지 않은 흔적이 여러 군데 있습니다.

## 초점을 끌고 가지 않기

하나 더 뺐어요. 원본은 3depth 팝업 밖으로 초점이 나가면, **애니메이션이 끝난 뒤 초점을 여는 버튼으로 강제로 되돌립니다.**

```js
popupSubmenu.addEventListener('transitionend', () => { lastClickedButton.focus(); }, { once: true });
```

의도는 알겠어요. "팝업이 닫혔으니 원래 자리로." 그런데 **사용자가 Tab으로 앞으로 나간 경우**에는 반대로 동작합니다. 다음 항목으로 가려고 Tab을 눌렀는데 초점이 뒤로 끌려와요. 한 번 더 누르면 또 끌려오고요.

닫기는 하되 **초점은 안 건드리게** 했습니다. 사용자가 Esc를 누르거나 제목 버튼으로 닫았을 때만 되돌려요. 그건 "돌아가겠다"는 의사 표시니까요.

```ts
expect(wrapper.find('.lnb-submenu-lv2').classes()).not.toContain('active');
expect(document.activeElement).toBe(outside);
```

## `page`와 `location`은 다릅니다

`aria-current`를 보태면서 기준을 하나 정했어요.

| 쓰는 곳 | 값 | 왜 |
| --- | --- | --- |
| SideNavigation · MainMenu · MobileMenu · Breadcrumb | `page` | 실제로 **다른 페이지**로 가는 링크 |
| InPageNavigation ("이 페이지의 구성") | `location` | 같은 페이지 **안의 위치**로 가는 링크 |

`page`는 "이게 지금 보고 있는 페이지"라는 뜻이에요. 한 페이지 안의 목차에 `page`를 붙이면 전부 현재 페이지라서 의미가 없어집니다. 그래서 거기만 `location`이에요.

## 테스트로 못박았습니다

역할 제거는 **되돌아가기 쉬운 결정**이에요. 나중에 누가 "APG 메뉴 패턴 따라야 하는 거 아냐?" 하고 다시 붙일 수 있습니다. 그래서 테스트에 적었어요.

```ts
it('menubar/menu/menuitem 역할을 쓰지 않는다 (방향키 없는 menu 역할 오용 보완)', () => {
  const wrapper = mountNav();
  expect(wrapper.find('[role="menubar"]').exists()).toBe(false);
  expect(wrapper.find('[role="menu"]').exists()).toBe(false);
  expect(wrapper.find('[role="menuitem"]').exists()).toBe(false);
});
```

테스트 이름에 **이유까지** 넣었습니다. 단정만 있으면 "왜 없어야 하지?" 하고 지워버리거든요.

```
npx vitest run src/components/SideNavigation
✓ 14 tests passed (1.01s)
```

## 오늘 정리

1. **"역할과 동작이 어긋날 때" 답이 하나가 아니에요.** 실제로 그 패턴처럼 생겼으면 동작을 채우고, 아니면 역할을 빼세요. 전체메뉴 탭은 전자, 사이드 메뉴는 후자였습니다.
2. **사이트 내비게이션은 메뉴 패턴이 아니에요.** APG 권고는 목록 + `aria-expanded` 버튼(disclosure navigation)입니다. `menubar`는 애플리케이션 메뉴용이에요.
3. **정의돼 있다고 돌아가는 건 아닙니다.** `setActiveCurrentPage`는 멀쩡히 있는데 `init()`이 안 불러요. 함수 존재를 동작 근거로 삼지 마세요.

본인 사이트에 LNB가 있다면 하나만 보세요. **개발자도구에서 `document.querySelectorAll('[role=menuitem]').length`를 찍고, 그 메뉴에서 방향키를 눌러보세요.** 숫자가 0이 아닌데 아무 일도 안 일어나면 같은 문제입니다.
